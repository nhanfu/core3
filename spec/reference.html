Styling

CSS system

The framework uses Tailwind CSS as the default styling system. Components apply utility classes directly in their draw() methods — no separate stylesheet files, no CSS-in-JS runtime, no naming conventions to learn.

Tailwind's utility-first approach aligns with the framework's philosophy: the component class is the source of truth for both structure and appearance. A developer reading draw() sees exactly what the component looks like without jumping to a stylesheet.

Utility classes in components

Components apply Tailwind classes via html.js chaining. The .cls() method accepts space-separated utilities:

class BadgeCell extends BaseComponent<{ value: string; color: string }> {
  draw(el: HTMLElement) {
    html(el)
      .span(this.state.value)
        .cls("inline-flex items-center px-2.5 py-0.5 rounded-full text-xs font-medium")
        .cls(this.state.color)    // dynamic: "bg-green-100 text-green-800"
      .end();
  }
}

class GridView extends BaseComponent<GridViewState> {
  draw(el: HTMLElement) {
    const grid = html(el).div()
      .cls("overflow-hidden rounded-lg border border-gray-200 shadow-sm");

    const header = grid.div().cls("grid-header bg-gray-50 border-b border-gray-200");
    for (const def of this.componentDefs) {
      header.div(def.label)
        .cls("px-4 py-3 text-left text-xs font-medium text-gray-500 uppercase tracking-wider")
      .end();
    }
    header.end();

    const body = grid.div().cls("divide-y divide-gray-200 bg-white");
    for (const row of this.state.rows) {
      const rowComp = this.createChild(RowComponent, { data: row });
      rowComp.draw(body);
    }
    body.end();
    grid.end();
  }
}

YAML class overrides

Component styles can be customized in the YAML page definition without touching the component class. The class key merges with or replaces the component's default classes:

components:
  - type: GridView
    id: po-grid
    source: purchase-orders
    class: "rounded-xl shadow-lg"        # override container classes

    components:
      - type: BadgeCell
        id: status
        field: status_label
        label: Status
        color: status_color
        class: "text-sm font-semibold"   # override per-component

      - type: CurrencyCell
        id: amount
        field: total
        label: Amount
        class: "tabular-nums text-right font-mono"

Tailwind config

The framework ships a base tailwind.config.js that covers ERP conventions — data-dense layouts, status colors, compact spacing. Projects extend it with their own brand tokens:

// tailwind.config.js — framework base
module.exports = {
  content: [
    "./pages/**/*.yaml",
    "./components/**/*.ts",
  ],
  theme: {
    extend: {
      colors: {
        // ERP status palette — used by BadgeCell, StatusItem, etc.
        status: {
          draft:    { bg: "#f3f4f6", text: "#374151" },
          pending:  { bg: "#fef3c7", text: "#92400e" },
          approved: { bg: "#d1fae5", text: "#065f46" },
          rejected: { bg: "#fee2e2", text: "#991b1b" },
        },
      },
      fontSize: {
        "grid":  ["0.8125rem", { lineHeight: "1.25rem" }],
        "grid-header": ["0.6875rem", { lineHeight: "1rem" }],
      },
    },
  },
  plugins: [
    require("@tailwindcss/forms"),
  ],
};

Escape hatch

When Tailwind utilities aren't enough — complex animations, third-party widget styling, or pixel-perfect print layouts — components can use .style() for inline CSS or inject a scoped <style> block. The framework does not prevent raw CSS; it just defaults to Tailwind for consistency across teams.

class SparklineCell extends BaseComponent<{ points: number[] }> {
  draw(el: HTMLElement) {
    const svg = html(el).svg()
      .cls("w-20 h-6")
      .style("shape-rendering", "geometricPrecision")   // inline escape hatch
      .attr("viewBox", `0 0 80 24`);
    // ... draw polyline from this.state.points
    svg.end();
  }
}
Security

Authentication & authorization

The framework does not implement authentication itself. It defines a pluggable interface that the host application implements — keeping the library infrastructure-agnostic.

interface IAuthProvider {
  getCurrentUser(): Promise<User | null>;
  hasPermission(user: User, action: string, resource: string): boolean;
  getSecurityContext(user: User): SecurityContext;
}

// The host app plugs in its own implementation
framework.configure({
  auth: new MyOAuth2AuthProvider({ ... })
});

Every data source query and component render checks permissions through this interface. Row-level security context values (like :allowed_branches) are injected into SQL parameters automatically.

Ecosystem

ERP integration points

Beyond database CRUD, real-world ERP systems need to talk to many external services. The framework provides adapter interfaces for these categories:

Integration

Email & Notifications

  • SMTP / SendGrid / SES for transactional emails
  • Push notifications (FCM, APNs) for mobile
  • SMS (Twilio) for delivery confirmations, OTP
Integration

File & Document Storage

  • S3 / Azure Blob / GCS for attachments
  • Document generation (PDF invoices, reports)
  • OCR / document parsing for AP automation
Integration

Payment & Financial

  • Payment gateways (Stripe, PayPal, ACH)
  • Accounting sync (QuickBooks, Xero, SAP)
  • Tax calculation (Avalara, TaxJar)
  • Currency exchange rate APIs
Integration

External ERP & CRM

  • SAP, Oracle, NetSuite connectors
  • Salesforce / HubSpot for CRM data
  • EDI (X12 / EDIFACT) for B2B exchange
Integration

Logistics & Shipping

  • Carrier APIs (FedEx, UPS, DHL)
  • Warehouse Management Systems (WMS)
  • Barcode / RFID scanning input
Integration

Identity & Directory

  • LDAP / Active Directory
  • SSO providers (Okta, Azure AD, Auth0)
  • SCIM for automated user provisioning
Integration

Workflow & Automation

  • Approval chains (POs, expense reports)
  • Webhook dispatch for event-driven integrations
  • Job queues (BullMQ, SQS) for async processing
  • Cron / scheduled tasks
Integration

Observability & Audit

  • Structured logging (Pino) with correlation IDs
  • Audit trail for compliance
  • APM (Datadog, New Relic, OpenTelemetry)
  • Error tracking (Sentry)
End to end

Full YAML page example

A complete purchase order page — layout, value/text data bindings, datasources, CRUD, and permissions in a single YAML file.

# page: purchase-orders.yaml
page:
  title: Purchase Orders
  auth:
    require: [po.read]
    row_filter: branch_id
  events:
    class: POPageEvents
    handles:
      - target: po-grid
        on: [cellClick, rowSelect, bulkAction]
      - target: po-detail
        on: [fieldChange, save]

layout:
  type: master-detail
  master:
    component: GridView
    id: po-grid
    source: recent-pos
    pagination: { size: 25 }
    components:
      - type: TextCell
        id: po-number
        field: po_number
        label: PO #
        width: 120
      - type: TextCell
        id: vendor
        val: vendor_id
        text: vendor_text
        label: Vendor
      - type: CurrencyCell
        id: amount
        field: total
        label: Amount
        class: "tabular-nums text-right"
      - type: BadgeCell
        id: status
        val: status
        text: status_text
        label: Status
      - type: DateCell
        id: created
        field: created_at
        label: Created
        format: relative
    filters:
      - field: status_label
        type: select
        options: [Draft, Pending, Approved, Received]
      - field: created_at
        type: date-range
    actions:
      - label: New PO
        permission: po.create
        route: /purchase-orders/new
  detail:
    component: form
    id: po-detail
    source: po-by-id
    sections:
      - title: Header
        fields: [vendor, ship_to, payment_terms, notes]
      - title: Line Items
        component: GridView
        id: po-lines-grid
        source: po-lines
        components:
          - type: TextCell
            id: item
            field: item_name
            label: Item
          - type: TextCell
            id: description
            field: description
            label: Description
          - type: NumberCell
            id: qty
            field: qty
            label: Qty
            editable: true
          - type: CurrencyCell
            id: unit-price
            field: unit_price
            label: Unit Price
            editable: true
          - type: CurrencyCell
            id: line-total
            field: total
            label: Total

datasources:
  # Query: server does all JOINs, returns flat 1D array
  - id: recent-pos
    db: postgres
    protocol: http
    roles: [admin, purchasing]
    permission: "po.read"
    query: |
      SELECT po.id, po.po_number,
             po.vendor_id, po.vendor_text,
             po.status, po.status_text,
             po.total, po.created_at
      FROM purchase_orders po
      JOIN vendors v ON v.id = po.vendor_id
      JOIN po_status_codes s ON s.code = po.status
      WHERE po.branch_id IN (:allowed_branches)
      ORDER BY po.created_at DESC

  # CRUD: default flags for simple operations
  - id: po-by-id
    db: postgres
    protocol: http
    table: purchase_orders
    roles: [admin, purchasing]
    permission: "po.manage"
    crud: [update, delete]           # default update + delete
    query: |
      SELECT po.*, v.name AS vendor_name, v.code AS vendor_code
      FROM purchase_orders po
      JOIN vendors v ON v.id = po.vendor_id
      WHERE po.id = :id
    params:
      id: { type: uuid, from: route }

    # Custom create — validation + multi-table insert
    create:
      language: javascript
      permission: "po.create"
      script: |
        const { vendor_id, ship_to, payment_terms, line_items } = ctx.params;
        if (!line_items?.length) {
          throw new ValidationError("PO requires at least one line item");
        }
        const po = await ctx.db.create("purchase_orders", {
          po_number: await ctx.db.nextSequence("po_number_seq"),
          vendor_id, ship_to, payment_terms,
          status: "draft",
          total: line_items.reduce((s, li) => s + li.qty * li.unit_price, 0),
          created_by: ctx.user.id,
          branch_id: ctx.user.branch_id
        });
        for (const li of line_items) {
          await ctx.db.create("po_line_items", { po_id: po.id, ...li });
        }
        return po;

  # CRUD: full default on line items
  - id: po-lines
    db: postgres
    protocol: websocket
    table: po_line_items
    roles: [admin, purchasing]
    permission: "po.edit"
    crud: true                       # all three: create, update, delete
    query: |
      SELECT li.id, li.item_id, p.name AS item_name,
             li.description, li.qty, li.unit_price,
             (li.qty * li.unit_price) AS total
      FROM po_line_items li
      JOIN products p ON p.id = li.item_id
      WHERE li.po_id = :po_id
    params:
      po_id: { type: uuid, bind: po-detail.id }
